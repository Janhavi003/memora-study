# API Contracts (Proposed)

Phase 0 defines contracts for frontend mock services and later Route Handlers. Schemas below are illustrative contract targets; runtime Zod schemas and response types must be implemented and tested before an endpoint is described as available. All JSON uses ISO-8601 timestamps in UTC unless a field is explicitly a date-only value.

## Conventions

- Base path: `/api`
- JSON request/response unless noted.
- Success payloads are wrapped as `{ "data": ... }`.
- Errors use `{ "error": { "code": "...", "message": "...", "details": [] } }`.
- IDs are opaque strings generated by the persistence layer.
- Validate all inputs with Zod. Do not accept client-calculated statistics or scheduler state as authoritative.

## Endpoints

### Decks
| Method | Route | Request | Success | Errors |
|---|---|---|---|---|
| GET | `/decks` | Query: `q?`, `subject?`, `sort?`, `page?`, `limit?` | `{data: DeckSummary[]}` | `VALIDATION_ERROR` |
| POST | `/decks` | `{name, description?, subject?}` | `201 {data: Deck}` | `VALIDATION_ERROR`, `CONFLICT` |
| GET | `/decks/:id` | — | `{data: DeckWithCards}` | `NOT_FOUND` |
| PATCH | `/decks/:id` | Partial `{name?, description?, subject?}` | `{data: Deck}` | `VALIDATION_ERROR`, `NOT_FOUND`, `CONFLICT` |
| DELETE | `/decks/:id` | — | `{data: {deleted: true}}` | `NOT_FOUND`, `CONFLICT` |
| POST | `/decks/:id/duplicate` | `{name?}` | `201 {data: Deck}` | `NOT_FOUND`, `VALIDATION_ERROR` |

### Generation
| Method | Route | Request | Success | Errors |
|---|---|---|---|---|
| POST | `/generation` | `{text, deckId?, maxCards, types[], subject?}` | `{data: {candidates: GeneratedCard[], warnings: string[]}}` | `VALIDATION_ERROR`, `PAYLOAD_TOO_LARGE`, `GENERATION_INSUFFICIENT_CONTENT` |
| POST | `/generation/import` | multipart file plus generation settings | Same as generation | `UNSUPPORTED_FILE_TYPE`, `PAYLOAD_TOO_LARGE`, `VALIDATION_ERROR`, `GENERATION_INSUFFICIENT_CONTENT` |

Generated candidates are previews; they are not persisted until explicitly saved. File allowlist initially `.txt`, `.md`, `.csv`. File bytes and extracted text must both be bounded.

## Data shapes (summary)

- `Deck`: `id`, `name`, `description?`, `subject?`, `createdAt`, `updatedAt`.
- `DeckSummary`: deck fields plus `cardCount`, `dueCount`, `lastStudiedAt?`.
- `Card`: `id`, `deckId`, `type`, `question`, `answer`, `options?`, scheduler fields, timestamps.
- `GeneratedCard`: temporary candidate ID, type, question, answer, options?, quality flags, duplicate flag.
- `Review`: `id`, `cardId`, `rating`, `reviewedAt`, `previousIntervalDays`, `nextIntervalDays`, `wasCorrect`.
- `Statistics`: totals and time series derived from stored data with documented period boundaries.

## Validation rules to implement

- Trim strings; reject blank required fields.
- Bound note and file sizes; bound `maxCards` and array lengths.
- Allow only known card types and ratings.
- Verify deck/card/session ownership relationships even in single-user local mode.
- Reject malformed IDs and unknown enum values.
- Do not trust client-supplied `cardCount`, `dueCount`, accuracy, interval, or ease factor.
- Avoid returning source notes or answers unnecessarily.
- Map expected failures to stable status codes: 400 validation, 404 missing, 409 conflict, 413 too large, 415 unsupported type, 422 insufficient content, 500 unexpected error.
